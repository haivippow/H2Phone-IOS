# Architecture

The UIKit controller calls `H2ConfigManager` to save a binary plist at `/var/mobile/Library/Preferences/com.h2changer.config.plist`. It contains `schema` (integer `1`), `enabled` (boolean), `profile` (one of four iPhone Pro Max names), and `enabledApps` (bundle ID array). Saving uses an atomic file write and posts `com.h2changer.config.changed`. The controller also publishes a compact per-app state through Darwin notifications for sandboxed target apps. The tweak reads that state and falls back to the plist. Invalid or absent configuration defaults to Fake OFF and DeviceTest as the selected app. Old Test A/B profile names fall back to the first current profile.

The independent manager is the future Agent boundary. A Windows C# controller can later communicate with an on-device agent, which validates requests and writes the same schema. The current MVP has no network listener or Windows dependency.

Each device profile is the single source for model/board/iOS identifiers, synthetic IDs, RAM/CPU, carrier, location, battery, and the browser-safe screen/CPU/touch/WebGL subset. Display geometry is applied only inside page JavaScript; native `UIScreen` remains original to protect keyboard, safe-area, rotation, and app layout behavior. Only the browser-safe subset is serialized into page JavaScript; UUID, IDFA, and IMEI values remain native-side and are not exposed through `window.__h2changerFingerprint`.

Debug Logs reads `/var/mobile/Library/Preferences/com.h2changer.debug.log`. Logs record config changes, not the device's original identifier values. The filter plist loads in UIKit apps and explicitly names MobileSafari; the runtime guard returns fake values only when global Fake is ON and the current bundle ID is in `enabledApps`. The 0.1.6 hook covers selected UIDevice, NSProcessInfo, sysctlbyname, uname, and MobileGestalt values, including the board configuration code. Safari (`com.apple.mobilesafari`) is the sole selectable Apple system app. Other Apple system apps and H2Changer itself always return original values.

The `H2WebUA` tweak group configures `WKWebView` instances in eligible selected apps, including Safari, before initialization. It adds a document-start, all-frames `WKUserScript`; for Safari, WebKit is responsible for transporting that script from MobileSafari's UI process to its WebContent process. The tweak does not attempt to create or find a `WKWebView` inside WebContent. It also applies a profile User-Agent, preserves the prior `customUserAgent`, and restores it when Fake is turned OFF and the view next navigates or reloads. The current main frame is updated immediately when a hooked navigation method runs; existing subframes receive the new state on their next navigation. Header and JavaScript results must be checked on the target iPhone; unrelated fingerprint properties remain unchanged.
